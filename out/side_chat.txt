GeoMapper Architecture
GeoMapper converts the denoised diffusion latent into spatial content, decoder modulation parameters, and evidence-confidence maps.
Inputs
For a 512 × 512 HR target and 128 × 128 LR input:
Input	Example shape	Role
Denoised latent ẑ₀	B × 4 × 64 × 64	Generated residual information
LR feature f64	B × C_lr × 64 × 64	Spatial evidence from LR
Text context	B × T × D_text	Optional prompt information
Mode token	B × D_mode	Distinguishes SR from edit mode

Internal Flow
Denoised latent ẑ₀: B×4×64×64
        │
        └── latent projection, 3×3 convolution
                         │
                         ▼
                  B×Cmap×64×64

LR feature f64: B×Clr×64×64
        │
        └── LR projection, 1×1 convolution
                         │
                         ▼
                  B×Cmap×64×64

Projected latent + projected LR
                         │
                         ▼
          Spatial residual block × 4
                         │
                         ▼
              Content: B×Cmap×64×64
                    ┌────┴─────┐
                    │          │
                    ▼          ▼
             Style branch   Policy branch
1. Spatial Content Branch
The latent and LR feature are projected to a common channel width and fused:
\[
h_0=P_z(\hat z_0)+P_{lr}(f_{64})
\]Four residual blocks then refine the fused tensor:
\[
h_{i+1}=h_i+F_i(h_i)
\]Output:
mapper.content: B × Cmap × 64 × 64
This remains spatial. Each position corresponds approximately to a location in the image.
2. Text and Mode Conditioning
Text tokens are pooled into a global conditioning vector. It is combined with the SR/edit mode embedding:
Text tokens → pooling/projection ┐
                                 ├→ conditioning vector
Mode token → embedding ──────────┘
This vector conditions the mapper and its output heads.
In SR mode, prompt influence should remain constrained. In edit mode, stronger prompt-controlled synthesis is allowed.
3. Layer-Wise Style/FiLM Branch
The content tensor is spatially pooled:
B×Cmap×64×64
      │
global average pooling
      ▼
B×Cmap
      │
+ text/mode condition
      ▼
style MLP
It generates one style vector for each decoder stage:
style_0 → decoder at 64×64
style_1 → decoder at 128×128
style_2 → decoder at 256×256
style_3 → decoder at 512×512
Each style vector controls feature channels using FiLM-like modulation:
\[
\operatorname{FiLM}(x)=\gamma\odot x+\beta
\]This controls texture and appearance without replacing spatial content.
4. Evidence-Confidence Head
A convolutional head predicts:
evidence_confidence: B × 1 × 64 × 64
Conceptually:
Content → 3×3 convolution → activation → 1×1 convolution → sigmoid
Values lie between 0 and 1:
near 1: generated detail is considered supported;
near 0: return toward the deterministic base;
near 0.5: uncertain or weakly calibrated.
The map is upsampled to 512 × 512 and applied to the SR residual:
\[
r_{\mathrm{accepted}}=
g_{\mathrm{evidence}}\odot \operatorname{HP}(r_{\mathrm{detail}})
\]5. Edit-Permission Head
The architecture also contains a separate edit-permission policy:
Content + prompt/mode → edit_permission: B × 1 × 64 × 64
Its meaning differs from evidence confidence:
Evidence confidence: “Is this SR detail sufficiently supported?”
Edit permission: “Where may the prompt intentionally alter content?”
In SR mode, edit permission is effectively disabled. In edit mode, it controls the full-band edit residual.
Outputs
GeoMapper returns approximately:
GeoMapperOutput
├── content:              B × Cmap × 64 × 64
├── styles[0]:            B × C64
├── styles[1]:            B × C128
├── styles[2]:            B × C256
├── styles[3]:            B × C512
├── evidence_confidence:  B × 1 × 64 × 64
└── edit_permission:      B × 1 × 64 × 64
GeoMapper is therefore the bridge between diffusion and the decoder: diffusion predicts what detail could exist, LR features preserve where it should align, styles determine how decoder channels express it, and policy maps determine how much generated content is permitted.

Ground Truth by Training Phase
For every paired sample:
HR target xHR: 3×512×512
LR observation y: 3×128×128
The LR is synthetically degraded from the native 10 m HR image.
Phase	Ground truth/supervision
1. Base	Native HR image and observed LR
2. VAE/decoder	True residual HR − base and native HR
3. Diffusion	VAE latent of the true residual and sampled diffusion noise
4. Joint	Native HR, observed LR, true diffusion velocity and real HR examples
5. Edit	Paired HR only for non-counterfactual prompts; prompt/mode supervision for edits

1. Deterministic Base Training
Prediction:
\[
\hat{x}_{base}=B(y)
\]Ground truths:
xHR: native Sentinel-2 10 m image;
y: synthetic 40 m LR observation.
Comparisons:
predicted base HR ↔ target HR
degrade(predicted base HR) ↔ clean LR
Losses:
Charbonnier against HR;
SSIM against HR;
gradient loss against HR;
degradation consistency against LR.
The model learns the conservative HR reconstruction.
2. Residual VAE and Decoder
The frozen base first produces:
\[
x_{base}=B(y)
\]The true residual target is:
\[
r^*=x_{HR}-x_{base}
\]Ground truths:
true residual r*;
native HR image;
local reconstruction-error map for evidence calibration.
The VAE learns:
\[
r^*\rightarrow z\rightarrow \hat r
\]The decoder path learns:
\[
x_{base}+\hat r_{detail}\approx x_{HR}
\]Losses supervise:
VAE residual reconstruction against r*;
output reconstruction against HR;
wavelet detail against HR;
KL against a standard-normal latent prior;
evidence confidence against actual local reconstruction quality.
The KL prior is mathematical regularization, not image ground truth.
3. Latent Diffusion Training
The frozen VAE encodes the true residual:
\[
z_0=E_{VAE}(x_{HR}-x_{base})
\]A timestep and known random noise are sampled:
\[
z_t=\alpha_tz_0+\sigma_t\epsilon
\]For velocity prediction, the exact target is computed from z0 and sampled noise:
\[
v_t=\alpha_t\epsilon-\sigma_tz_0
\]Ground truths:
clean latent z0;
sampled noise ε;
computed target velocity vt.
The U-Net predicts:
\[
\hat v_\theta(z_t,t,\text{conditions})
\]and is trained against vt.
There is no direct HR loss in diffusion-only training. Its target is the exact diffusion velocity associated with the true residual latent.
4. Joint Fine-Tuning
Ground truths:
native HR image;
clean LR observation;
true residual latent;
target diffusion velocity;
real HR patches for discriminator supervision.
Generator supervision:
generated HR ↔ native HR
degraded generated HR ↔ clean LR
predicted velocity ↔ target velocity
generated wavelets ↔ target wavelets
Discriminator supervision:
Input	GAN label
Native HR + corresponding LR	Real
Generated HR + corresponding LR	Fake

Losses include:
Charbonnier;
SSIM;
LPIPS when available;
wavelet loss;
LR consistency;
diffusion velocity loss;
evidence calibration;
low-weight adversarial loss.
The discriminator’s real/fake label is GAN supervision, while the native HR remains the paired image target.
5. Prompt/Edit Fine-Tuning
This phase has two sample types.
Matched, null or paraphrased prompt
The original HR remains valid supervision:
generated output ↔ native HR
These samples can use reconstruction, consistency and evidence losses.
Counterfactual/mismatched prompt
There is no paired ground-truth edited image.
For example, given an agricultural HR patch and a prompt requesting dense urban blocks, the original HR is not the correct target for the requested edit.
Therefore, paired reconstruction losses are masked for these samples. Supervision comes from:
prompt-image alignment;
adversarial realism;
edit localization;
edit-permission coverage;
soft LR consistency;
diffusion supervision;
synthetic-edit mode policy.
These constraints do not provide true counterfactual ground truth. The result must be labeled synthetic.
Important Distinction
The project has true paired supervision only for synthetic 40 m → native 10 m SR:
\[
y=\mathcal D(x_{HR}),\qquad x_{HR}\text{ is known}
\]It does not have true ground truth for:
real 40 m sensor imagery with unknown degradation;
10 m to 2.5 m SR;
prompt-requested counterfactual edits.
Those outputs cannot be evaluated as ordinary paired reconstruction without an independently acquired and registered target.

The confusion comes from the term “GAN decoder.” There is no separate object called “GAN” inside the inference architecture.
A GAN is a training arrangement between two networks:
Generator: the existing GeoDiff-GAN image-generation path.
Discriminator: an additional network used only during phases 4 and 5.
Where GAN Appears
                    GENERATOR
LR ──> Swin base ───────────────────────────────┐
                                               │
LR ──> LR encoder                              │
             │                                 │
Text ────────┼──> Diffusion U-Net              │
             │          │                      │
             │     denoised latent             │
             └────> GeoMapper ──> SR decoder ──┤
                                               ▼
                                      Generated HR
                                               │
                       ┌───────────────────────┴──────────────┐
                       ▼                                      ▼
             Multi-scale PatchGAN                  Wavelet discriminator
                       ▲                                      ▲
                       │                                      │
                    Real HR                              Real HR
Everything from LR to generated HR collectively acts as the generator:
Swin base
+ residual VAE
+ LR encoder
+ diffusion U-Net
+ GeoMapper
+ residual decoder
The GAN does not replace the VAE decoder or diffusion U-Net.
The Two Discriminators
Multi-scale PatchGAN
Inputs:
Real pair:  native HR + corresponding LR
Fake pair:  generated HR + corresponding LR
It evaluates local realism at several spatial scales:
road and building boundaries;
field structures;
local textures;
larger spatial arrangements.
It outputs grids of real/fake scores rather than one classification value.
Wavelet Discriminator
The real and generated HR images are transformed into high-frequency Haar wavelet bands:
HR image
  ├── LH: horizontal-related detail
  ├── HL: vertical-related detail
  └── HH: diagonal detail
The discriminator determines whether these high-frequency bands resemble those of real Sentinel-2 HR patches.
Which Training Phases Use GAN?
Phase	GAN used?
1. Swin base	No
2. VAE + decoder	No
3. Diffusion U-Net	No
4. Joint fine-tuning	Yes
5. Edit fine-tuning	Yes
Inference	No discriminator

GAN training starts only after the other modules have learned meaningful reconstruction.
Joint Training Sequence
For each batch:
Discriminator update
Native HR ───────────────> discriminator ──> should predict REAL
Generated HR.detach() ───> discriminator ──> should predict FAKE
The generated image is detached so this update changes only the discriminators.
Generator update
Generated HR ──> discriminator ──> generator wants a REAL score
This gradient passes backward:
Discriminator score
    ↓
Generated HR
    ↓
Residual decoder
    ↓
GeoMapper
    ↓
Diffusion U-Net
Thus, the discriminator teaches the generator to produce more realistic detail.
Why It Is Absent at Inference
After training, the discriminator is discarded:
LR → generator → HR output
A discriminator does not create pixels. It is a learned training loss that evaluates realism.
Therefore, your architecture diagram should show two sections:
Inference architecture:
LR → base/diffusion/GeoMapper/decoder → HR

Training-only adversarial branches:
Generated HR + LR → PatchGAN discriminator
Real HR + LR      → PatchGAN discriminator

Generated HR + LR → wavelet discriminator
Real HR + LR      → wavelet discriminator
The name “GAN decoder” only means the residual decoder is trained partly using adversarial gradients. Technically, the complete generation pipeline is the GAN generator, while PatchGAN and the wavelet discriminator form the training-only adversarial side.
